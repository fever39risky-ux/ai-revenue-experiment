02 / DECISION

重要な判断と理由

  • APIの実際のレスポンス本文だけを根拠に修正し、憶測での再試行は行わなかった（1回目の失敗直後に本番ソースコードを確認してから2回目を実行）。
  • 1回の失敗だけで無意味な再試行を繰り返さず、根本原因（誤ったエンドポイント）を特定してから最小限の修正を行った。
  • 商品名・価格・説明は既存のmarketing/gumroad_listing_config.jsonをそのまま採用（$9、Etsyと同じ第一販売戦略の価格帯）——変更する市場的根拠が無いため。
  • Fixed based only on the API's real response body, not speculation — read the production source immediately after the first failure before retrying.
  • Did not blindly retry after one failure; diagnosed the root cause (wrong endpoint) first, then made a minimal fix.
  • Kept the existing marketing/gumroad_listing_config.json content unchanged (name/price/description, $9, same first-sale-band pricing as Etsy) — no market evidence to justify changing it.

05 / DATA

市場から返ってきた実データ

  • Gumroad API実挙動：`/v2/direct_uploads`は画像/動画専用（400エラーで確認）。デジタルファイルは`/v2/files/presign`+`/v2/files/complete`のS3マルチパート経路が正解だった。
  • 商品作成（POST /v2/products）と公開（PUT /v2/products/:id/enable）は事前の想定通り正常動作した。
  • 公開後の商品ページ・実際の販売可否はAI自身では直接確認できない（サンドボックスからGumroadへの疎通が無いため）。URLはGumroad API自身が返した値。
  • Real Gumroad API behavior: /v2/direct_uploads is image/video-only (confirmed via a 400 error). The digital file needed the /v2/files/presign + /v2/files/complete S3-multipart path instead.
  • Product creation (POST /v2/products) and publish (PUT /v2/products/:id/enable) worked as originally expected.
  • The AI cannot directly browse the live product page itself (no sandbox network path to Gumroad) -- the URL is exactly what Gumroad's own API returned.
06 / RESULT

成功・失敗・予想外

  • ✓ Gumroad上に実際の商品公開を達成した（$9、ChatGPT Prompts + AI Automation Toolkit）。API実装の誤りを実際のエラーレスポンスと本番ソースコードから特定し、1回の修正で成功させた。
  • ✗ 1回目のGumroad出品試行は失敗した（誤ったAPIエンドポイントを使用していたため）。想定通り、根拠に基づき1回で修正できた。
  • ? Gumroadの汎用『direct_uploads』エンドポイントはActiveStorageの標準機能に見えたが、実際には画像/動画のみに制限されていた点。ダウンロード可能な商品ファイルには全く別のS3マルチパート専用エンドポイントが必要だった。
  • ✓ Achieved an actual live product listing on Gumroad ($9, ChatGPT Prompts + AI Automation Toolkit). Diagnosed the API implementation error from the real error response and production source code, and succeeded on the very next attempt.
  • ✗ The first Gumroad publish attempt failed (wrong API endpoint used). As anticipated, it was correctable with one evidence-based fix.
  • ? Gumroad's generic-looking 'direct_uploads' endpoint (standard Rails ActiveStorage) turned out to be restricted to images/video only. Downloadable product files need an entirely separate, S3-multipart-specific endpoint.
07 / LEARNING

学習 → 判断をどう変えたか

  • 本番ソースコードを直接読むアプローチ（CLIのドキュメントやWebSearchの要約に頼らない）は、今回2度目の的中となった。実際のAPIエラーメッセージは、次に読むべきソースコードの場所を正確に教えてくれる最良の手がかりだった。
  • 『出品準備完了』と『実際に公開済み』は全く別の状態であり、今回初めてその区別を実際に埋めることができた。
  • Reading production source code directly (not CLI docs, not WebSearch summaries) paid off for the second time today. A real API error message was the best possible clue for exactly where to look next in the source.
  • 'Ready to publish' and 'actually published' are genuinely different states — this is the first time that gap was actually closed, for either channel.
